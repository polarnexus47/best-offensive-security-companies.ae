What Is an Offensive Security Company?

An offensive security company tests a client's systems the way an attacker would, under written authorisation, and reports what it exploited and how to fix it. Its core services are penetration testing, red teaming, social engineering and application testing. The category differs from defensive security, which monitors and responds, and from managed security, which runs those defensive operations as a service. What offensive security companies do

Six services make up the core of the category. Each one answers a different question about your exposure.

Vulnerability assessment and penetration testing (VAPT)

Testers identify weaknesses in defined systems and then exploit them to prove impact. A vulnerability assessment lists possible weaknesses; a penetration test confirms which ones an attacker can use. The deliverable is a report with evidence and remediation steps.

Red teaming

A red team pursues a goal, such as reaching customer data, using whatever route works: phishing, a weak perimeter service, a stolen credential. It measures whether your people and tooling detect and stop a realistic intrusion, not how many bugs exist.

Purple teaming

Attackers and defenders work in the same room. The offensive side runs a technique, the defensive side checks whether detection fired, and both tune rules until it does.

Application and API testing

Testers examine web, mobile and API logic: authentication, session handling, access control and business-logic abuse. Standards such as the OWASP Web Security Testing Guide structure this work.

Social engineering

Phishing, phone pretexts and physical access tests show how staff respond to deception, which technical controls rarely cover.

Cloud and wireless testing

Testers review cloud configuration, identity permissions and wireless networks that extend your perimeter beyond the office.

Three categories are often confused in vendor marketing. The table separates them by purpose and output.

Offensive security feeds the other two. Findings from a test become hardening tasks for the defensive team, and a red team debrief becomes detection rules for the managed SOC.

Where the lines blur: a vulnerability scan is not a penetration test, and a penetration test is not a red team. A scan lists possible weaknesses from tool output. A penetration test exploits a defined scope. A red team pursues an objective across the organisation. Providers sometimes use the terms loosely, so check what the quote says will be done. Types of offensive security provider

Providers fall into three groups. The ranking on this site uses the same groups as tiers.

Boutique offensive specialist (Tier 1). Offensive testing is the whole offering. Senior testers do the work, and the company usually sells fixed-scope projects. This model suits buyers who need depth on a specific application, network or red team objective.

Offensive-led consultancy (Tier 2). Penetration testing and red teaming lead the service list, alongside compliance, privacy, advisory, forensics or training services. This model suits buyers who need testing mapped to a framework such as PCI DSS or a sector rule.

Platform or managed-security-led provider with an offensive arm (Tier 3). The main product is monitoring, detection and response, and testing is one line among several. This model suits buyers who already need a managed service and want one vendor.

None of the three is better in every case. The right model depends on whether depth, compliance mapping or continuous monitoring is the priority. The guide to choosing a provider covers the decision.

How to tell which type a provider is. Read the provider's own service list in order. If testing is the whole list, it is a specialist. If testing leads and sits beside compliance, advisory, forensics or training work, it is offensive-led. If a SOC, managed detection and response or a platform leads the list, it is managed-security-led. Then check the report description: a provider that states proof of concept, severity scoring and remediation guidance is describing a deliverable you can evaluate.

Three example engagements

These examples are generic. They show what scope, deliverable and outcome look like; durations vary by scope and are fixed in the proposal.

Three example engagements
EngagementScopeDeliverable
Web application test before launchOne application, test accounts for each user role, staging or production as agreedReport with each finding, proof of concept, CVSS score and fix guidance; retest after the development team patches
Internal network penetration testA defined internal network segment, with the tester starting as a connected user with no privilegesAttack path from initial access to the agreed objective, such as domain administrator, with evidence and remediation
Red team operationAn agreed objective, such as access to a named data store, with rules of engagement and an emergency stop contactTimeline of actions, what was detected and what was not, and detection recommendations for the defensive team

Every engagement runs through the same stages:

  1. Scoping. The provider and client agree on assets, user roles, environments and objectives.
  2. Rules of engagement. Testing windows, contacts, prohibited actions and an emergency stop are written down and signed.
  3. Testing. Testers map, probe and exploit within the scope, and escalate critical findings during the work.
  4. Reporting. Findings are documented with evidence, severity and remediation steps.
  5. Debrief. The provider walks the client's technical and management teams through the results.
  6. Retest. After fixes, the provider confirms which findings are closed.

Each engagement starts with a signed scope and rules of engagement. Testing outside that scope is not authorised.

Offensive security is not OffSec

"Offensive security" is the name of a discipline. OffSec, formerly Offensive Security, is a separate company: a US-based training and certification provider headquartered in New York, known for the OSCP certification and the Kali Linux distribution. Employing OSCP-certified staff does not make a company part of OffSec. Search results for "offensive security companies" often mix the two.
