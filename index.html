What counts as offensive security

Offensive security is the practice of attacking your own systems, with authorisation, to find exploitable weaknesses before a real attacker does. Offensive security companies sell that work as a service: scoped tests, a written report and a retest.

Included in this ranking

  • Vulnerability assessment and penetration testing (VAPT)authorised exploitation of defined targets, with evidence.
  • Red teaminga goal-driven simulated attack against people, process and technology.
  • Purple teamingattackers and defenders working together to tune detection.
  • Social engineeringphishing and pretext tests against staff.
  • Application and API testingweb, mobile and API logic and access control.
  • Cloud and wireless testingconfiguration and network exposure outside the office perimeter.

Not included

  • SOC-as-a-service and managed detection and response sold as the main product.
  • Product resale and licence reselling.
  • Compliance-only consulting with no hands-on testing.

Companies in the third tier sell managed detection or SOC services as their main product and offer testing as an additional line. They are included because they publicly describe offensive services, and they are ranked below specialists because offensive work is not the whole offering.

How the offensive security companies were ranked

The ranking uses a tier model first and breadth of public evidence second. Tier 1 holds offensive-only specialists. Tier 2 holds offensive-led firms that pair testing with compliance, advisory, forensics or training work. Tier 3 holds managed-security-led providers with an offensive line. Inside a tier, companies are ordered by how many testing types they state publicly and how clearly they describe reporting.

Six criteria

  • Offensive specialisationshare of the stated offering that is hands-on testing.
  • Testing depthmanual exploitation versus scanner output, and named test types.
  • Scope coverageweb, mobile, API, network, cloud, wireless, social engineering, red team.
  • Reporting transparencystated report contents, proof of concept, severity scoring, retest.
  • Delivery model and named methodologywho performs the work and how it is run.
  • UAE market fitstated UAE presence and regional programmes.

Evidence rules: a fact appears only if the company's own site or a named directory states it. Unverified items read "Not stated". No numeric scores are published, and accreditations do not change the order. Read the full methodology and the editorial policy.

Seven questions to ask before you sign

Ask each shortlisted provider these questions in writing. A clear answer is a pass; an evasive answer is a fail.

  1. Which methodology do you follow, and can you name it (for example OWASP WSTG or NIST SP 800-115)? A named method makes the work repeatable and auditable.
  2. What does the report contain: proof of concept, CVSS score, remediation steps? Without evidence, findings cannot be reproduced or fixed.
  3. Is a retest included, and how many rounds? A retest confirms the fixes actually closed the findings.
  4. Who performs the work, and which testers will be on my project? Depth depends on the people, not the brand.
  5. Which parts of my scope will you not cover? Every test has limits, and a provider should state them.
  6. What rules of engagement and scope exclusions will we sign? They protect production systems and define what is authorised.
  7. Which accreditations do you hold, and where can I verify them? Check the issuing directory, not the logo on a website.

Questions 1 to 6 are expanded in How to choose an offensive security company. Question 7 is expanded in Offensive security certifications explained.

Frequently asked questions about offensive security companies

What is an offensive security company?

An offensive security company tests a client's systems the way an attacker would, under written authorisation, and reports what it exploited. Typical services are penetration testing, red teaming, social engineering and application testing. The output is a report with evidence and remediation steps. Providers that mainly sell monitoring or SOC services are managed security companies, even when they add a testing line.

What is an example of offensive security?

A web application penetration test is a common example. Testers map the application, try to bypass authentication and access control, exploit what they find with proof of concept, and document the impact. Another is a red team operation: a goal-driven simulated intrusion, for instance reaching a sensitive database from an external phishing email, run without notice to most defenders.

What is an offensive security platform?

An offensive security platform is software that supports testing, such as penetration testing as a service portals, breach and attack simulation tools or attack surface scanners. It delivers findings continuously or on demand. A platform does not replace a manual test by itself. Check whether named testers validate the findings and whether the report contains proof of concept and remediation guidance.

What is the difference between a penetration test and a red team?

A penetration test is a bounded technical assessment of defined systems, with the client's team usually informed, that finds as many exploitable weaknesses as the scope allows. A red team is a goal-driven simulation of a real adversary across people, process and technology, usually unannounced to most defenders. The penetration test measures exposure; the red team measures detection and response.

Which cybersecurity or pentest company is best in Dubai or Abu Dhabi?

No single company is best for every buyer. This ranking compares ten providers by tier, stated testing scope and reporting transparency. Specialists suit deep manual testing; managed-security-led providers suit buyers who also want monitoring. Shortlist two or three providers, send each the same written scope, and compare methodology, report contents, retest terms and the named testers before choosing.

Do I need a CREST-accredited provider in the UAE?

Only in specific cases. A CREST page from July 2024 says Dubai government, semi-government and critical information infrastructure entities must buy penetration testing and incident response from Dubai Cyber Force certified companies, while another CREST page still calls the programme expected to become mandatory from 31 July 2024. Confirm status with DESC. Other buyers are not required to use CREST by the sources reviewed.

Which UAE regulations require penetration testing?

PCI DSS v4.0.1 Requirement 11.4 explicitly requires penetration testing for entities handling card data. The Dubai Cyber Force programme sets provider requirements for Dubai government work. The UAE IA Regulation and PDPL pages on the government portal describe general security duties and name no testing clause. DIFC and ADGM have separate data protection regimes. Check each rule's full text.

How long does a pentest take and what should the report contain?

Duration depends on scope: the number of applications, user roles, hosts and the depth of manual work. The provider should state timeline and scope in a signed proposal. A usable report contains an executive summary, methodology, scope, each finding with severity, CVSS score, proof of concept and remediation steps, and a retest result after fixes.

Do offensive security firms investigate crypto theft?

Some do, but testing and forensics are different services. Penetration testing finds weaknesses in exchanges, wallets and key management before an attack. Forensics traces stolen funds and preserves evidence after one. Check each company profile for a stated forensics service, and ask for the deliverable format. Tracing supports investigation; it does not guarantee recovery of funds.
